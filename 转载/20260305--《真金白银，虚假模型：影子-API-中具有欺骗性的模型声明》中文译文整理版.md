## 标题

**真金白银，虚假模型：影子 API 中具有欺骗性的模型声明**

Yage Zhang，Yukun Jiang，Zeyuan Chen，Michael Backes，Xinyue Shen，Yang Zhang CISPA 亥姆霍兹信息安全中心

## 摘要

访问前沿大语言模型（LLM），如 GPT-5 和 Gemini-2.5，通常会受到高昂价格、支付门槛以及地区限制的阻碍。这些限制推动了影子 API 的扩散。所谓影子 API，是指第三方服务商声称可通过间接接入的方式，在不受地区限制的条件下提供官方模型服务的访问能力。尽管它们被广泛使用，但这些影子 API 所返回的结果是否与官方 API 一致，目前仍不明确；这引发了人们对依赖这些服务的下游应用可靠性以及相关研究结论有效性的担忧。本文首次对官方 LLM API 与相应影子 API 进行了系统审计。

我们首先识别出 17 个影子 API，它们已被 187 篇学术论文使用。截至 2025 年 12 月 6 日，其中最流行的一个已累计获得 5,966 次引用、58,639 个 GitHub stars。随后，我们从实用性、安全性和模型验证三个维度，对其中三个具有代表性的影子 API 进行了审计，并发现了影子 API 存在欺骗行为的间接与直接证据。具体而言，我们发现其性能偏差最高可达 47.21%，安全行为存在显著且不可预测的不一致，并且在 45.83% 的模型指纹测试中未通过身份验证。这些欺骗性做法严重破坏了科学研究的可复现性与有效性，损害了影子 API 用户的利益，也损害了官方模型提供方的声誉。

## 1 引言

前沿大语言模型已经改变了众多领域，并逐渐成为科学研究与日常应用的关键基础设施。借助先进的推理能力与领域知识，这些模型在复杂任务中表现出更强的有效性。由于许多前沿 LLM 属于专有模型，或者需要大量计算资源，本地部署通常不可行。近年来，人们主要通过 OpenAI、Google 等公司提供的商业 API 来访问这些模型。

然而，官方 API 往往伴随着高昂的费用、支付障碍以及严格的地理访问限制。例如，OpenAI 官方 API 在中国、俄罗斯、伊朗等若干地区无法直接访问。因此，一个庞大的第三方提供商市场开始出现，以更低的价格、且不受地区限制的方式提供兼容端点。我们将这些服务称为**影子 API**：它们声称通过间接接入提供与官方 LLM 相同的输出。到 2025 年 12 月 6 日，最流行的影子 API 已经累计获得 58,639 个 GitHub stars，并被 187 篇学术论文使用，这些论文累计被引用 5,966 次。多数论文已被 ACL、CVPR、ICLR 等顶级会议接收。

近期研究已指出，开源模型 API 的访问本身就可能存在不可靠性，这进一步引发了一个严重问题：影子 API 是否真的能忠实替代官方 API？许多用户把影子 API 当作官方 API 的可互换替代方案，只从"能不能用"的效用角度看待接入问题，而没有进一步验证。但从供应链视角看，影子 API 实际上是黑箱代理：请求会在多个未经授权的节点之间被路由、处理，并可能遭到篡改。借助官方品牌名义，以低价提供不稳定或被错误标识的模型，影子 API 不仅会分流合法服务商的收入，也可能由于用户体验下降或受限地区的违规接入，进一步损害官方模型的声誉。

本文试图通过回答以下三个研究问题，揭示影子 API 市场的根本不透明性：

* **RQ1：当前有哪些影子 API，它们被使用到了什么程度？**
* **RQ2：对于同样的请求，影子 API 的表现是否与官方 API 一致？**
* **RQ3：模型验证方法能够提供哪些证据？**

为回答 RQ1，我们识别了 17 个影子 API，并调查了 187 篇学术论文，以量化这些服务的普及程度。为回答 RQ2，我们从效用与安全两个角度进行了多维基准评测。令人警惕的是，我们的实验显示影子 API 与官方 API 之间存在显著性能不一致。例如，在 MedQA 这样的高风险医学基准上，Gemini-2.5-flash 通过官方 API 的准确率为 83.82%，但通过所有被审计的影子 API 时，准确率都骤降到约 37.00%。此外，相较官方 API，影子 API 在安全行为上表现出不可预测性，有时会低估危害性约 0.23，有时又会将危害性放大到接近两倍。最后，为回答 RQ3，我们使用模型指纹识别和输出元数据分析来审计这些影子 API，并给出了模型替换的具体证据：在 24 个被评估的端点中，45.83% 未通过指纹验证，另有 12.50% 与官方模型之间表现出显著的余弦距离偏差。

### 本文贡献

* 识别出 17 个被广泛使用的影子 API，并首次对其与官方基线进行系统审计。
* 证明影子 API 在实用性和安全性评估中经常失效且不可靠，揭示其具有欺骗性的模型声明。
* 证明基于模型指纹和元信息的验证方法，能够为影子 API 与官方 API 之间的差异提供支持性证据。
* 提出提升来源意识、降低使用 LLM API 带来的可复现性风险的建议。

### 披露说明

作者表示，他们致力于将这些发现以负责任的方式报告给官方模型提供商以及使用影子 API 的论文作者，并已收到部分回应。

## 2 预备知识

### 2.1 背景

LLM 已迅速成为现代自然语言处理、机器学习，甚至计算机视觉研究的基础，也成为构建个人智能体的核心。对 16,193 篇论文的分析表明，到 2024 年，超过 60% 的 NLP 论文、约 20% 的 ML 论文，以及接近 10% 的 CV 论文都与 LLM 相关。与此同时，前沿专有模型的访问受到了严格控制。提供商出于法律和安全原因，会对某些地区限制 API 访问。例如，Anthropic 明确禁止向不支持地区销售服务；OpenAI 也警告称，若从不支持的国家访问或转售其 API，账户可能会被暂停。

这些限制与 AI 研究中的地理现实发生了冲突：像 AAAI、CVPR 等主要 AI 会议，会收到来自某些受限地区（如中国）的大量投稿和录用论文。

除了地域障碍，高昂费用也给用户带来了压力。前沿 LLM API 的定价通常面向企业客户，对于个人研究者或学生而言往往难以承受。有研究指出，当前许多 LLM API 的使用模式在没有交叉补贴的前提下，对小规模用户来说是不可持续的。这推动了一个商业化灰色市场的发展：它们以更低价格、并绕开地理限制，提供对前沿 LLM 的访问。

此外，官方服务条款通常禁止任何形式的 API key 转售或再分发。中国政府监管也要求 AI 服务必须遵守相关法律与行政要求。因此，这些影子 API 服务商既违反了服务合同，也可能违反适用的监管要求。这些趋势表明，学术界对前沿模型的需求，与官方分发渠道的限制之间存在越来越明显的脱节，从而推动了大规模非官方第三方服务市场的形成。

### 2.2 定义

为便于表述，本文引入"**影子 API**"这一术语，用来描述具有以下两个特征的第三方 LLM API 服务：


1. **间接访问**
2. **在受限地区提供访问能力**

### 2.3 相关工作

LLM 会表现出独特的语言模式与特征，这些模式可被视为"指纹"，从而用于识别一段内容究竟由哪个模型生成。LLMmap 提出了一种主动式指纹方法：通过向模型发出精心设计的查询，估计其回答在不同参考模型下的似然。另有工作审计了开源模型 API 中的模型替换问题，并评估了可信执行环境作为验证模型完整性的硬件级解决方案。与之不同，本文关注的是影子 API——一种以黑箱方式运行的间接服务。另有关于模型抽取与模仿的研究指出，较小模型可以被训练来模仿前沿模型的输出，这使得用户仅凭表层交互更难分辨模型是真实官方版本，还是蒸馏/仿制版本。然而，对于这一缺乏监管的影子 API 市场，系统性的审计研究仍基本缺位。

## 3 影子 API 的生态图景

为回答 RQ1，作者从研究界与开源社区两个维度，量化影子 API 的使用情况。

### 3.1 影子 API 的收集

作者从 ICLR 2024 和 ACL 2024 的录用论文开始筛选，共计 2,113 篇带代码论文。通过系统解析论文摘要和脚注中的代码仓库链接，作者识别出 92 个通过 GitHub 仓库使用 LLM API 的项目。其中，21 篇论文（22.8%）使用了至少一个影子 API 端点。随后，作者又在 GitHub 中搜索这些端点 URL，继续寻找调用同一 URL 的其他仓库，并收集其所属会议、机构、国家、引用量以及 GitHub stars 等信息。作者不断迭代这一过程，直到不再发现新的影子 API 端点为止。

### 3.2 影子 API 的普及程度与影响

#### 使用情况

最终，作者识别出 **17 个影子 API**，它们出现在 **187 篇研究论文** 中。其中 **116 篇（62.03%）** 已被同行评审会议或期刊接收，包括 ACL、CVPR、ICLR 等。最广泛使用的影子 API 累积获得 **5,966 次引用**，其关联 GitHub 仓库合计获得 **58,639 个 stars**。这些结果表明，影子 API 在研究领域已经被广泛采用。论文中的图 2 还显示，多数作者来自某些受限地区（例如中国）的机构，这些论文也往往获得了较高引用和较强的 GitHub 社区参与度。

#### 基础设施

在识别出的 17 个影子 API 中，有 **11 个** 构建于开源 AI 模型聚合与再分发系统之上，主要是 **OneAPI** 及其衍生项目 **NewAPI**。OneAPI 是一种面向自托管部署的开源工具，可将多家商业 LLM 提供商的接口统一为兼容 OpenAI 的格式。该类基础设施支持 API key 管理、二次分发、请求路由、自动重试等功能，从而比官方 API 更容易被利用、转售和滥用。

#### 合规性与透明度

第三方 API 服务的合规性与透明度非常关键，因为这关系到用户权益能否得到法律保障，也关系到服务是否真的如其所述、并能持续稳定运行。作者通过检查服务商身份、企业注册与服务公开信息等内容，评估了影子 API 的合规状态。结果显示，在这 17 家服务中，有 **15 家** 由个人运营，缺乏透明身份信息与可验证来源；只有 **1 家** 通过中国 ICP 备案拥有有效企业注册。与此同时，这些服务商生态高度不稳定，已有两家停止运营。此外，所有服务商都会频繁更换上游模型来源，却未向用户提供透明、详尽的通知。这说明大多数影子 API 都在缺乏有效合规验证与治理保障的情况下运行，使用户面临较高的法律与运营风险。

### RQ1 结论

影子 API 已经非常流行，但其运行几乎没有透明度和治理保障。大多数提供商缺乏可验证身份、稳定基础设施，以及对上游模型来源的披露。

## 4 性能评估

为回答 RQ2，作者从**实用性**和**安全性**两方面评估影子 API 的性能。作者没有直接复现已有研究，而是选择受控基准测试，以减轻影子服务本身不稳定带来的影响，并保护受影响研究者的匿名性。

### 4.1 实验设置

#### 模型

为了覆盖不同提供商与模型，作者基于 2025 年 11 月 OpenRouter 的 LLM 使用量排行榜选择目标模型，并划分为三个主要模型家族：

* **F-A（OpenAI）**：GPT-4o-mini、GPT-5、GPT-5-mini
* **F-B（Google）**：Gemini-2.0-flash、Gemini-2.5-flash、Gemini-2.5-pro
* **F-C（DeepSeek）**：DeepSeek-Chat、DeepSeek-Reasoner

在科学领域评估中，作者评估上述全部 8 个模型；在敏感领域与安全评估中，作者从每个家族选一个更具代表性的模型：GPT-5-mini、Gemini-2.5-flash、DeepSeek-Chat。

#### 影子 API 选择

作者以**论文引用量**和 **GitHub stars** 作为流行度指标，并将所有影子 API 匿名化，使用 A、B、C 等代号。具体实验选取了 **影子 API A、E、H**，因为它们同时满足三个条件：


1. 在引用量和 GitHub stars 上较为流行；
2. 公开可访问；
3. 对三大模型家族覆盖较完整。 所有官方基线则直接通过相应官方 API 获取。

#### 实验细节

为降低波动，所有实验都取 3 次试验的平均值，并报告准确率及其标准差。效用与安全评估通过 API 查询完成，不需要本地 GPU；而 LLMmap 指纹方法则借助 NVIDIA DGX A100 进行数据库训练。

### 4.2 实用性评估

#### 基准与方法

作者在**科学领域**与**敏感领域**分别评估模型效用：

* 科学领域：AIME 2025（竞赛级数学题）、GPQA (Diamond)（博士级科学问题）
* 敏感领域：MedQA (USMLE)（医学）、LegalBench (Scalr) 的 Rule-Application 与 Rule-Conclusion 子集（法律）

#### 科学领域表现

总体上，官方 API 通常构成性能上限。影子 API 中，**影子 API E** 的一致性最好，与官方 API 的平均偏差仅为 **2.64%**；在某些情况下（如 GPT-5-mini 在 GPQA 上），它甚至会略高于官方 API **1.18%**。相比之下，官方 API 的性能波动很小，而影子 API 波动明显更大。尤其是 **影子 API A** 和 **影子 API H**，与官方 API 的平均准确率差距分别达到 **9.81%** 和 **6.46%**。

虽然某些影子 API 在非推理任务上的表现接近官方 API，但在强调推理能力的模型上，性能会明显下降。尤其在 **AIME 2025** 上，影子 API A 出现严重准确率下跌：Gemini-2.5-pro 下降 **40.00%**，DeepSeek-Reasoner 下降 **38.89%**。这表明，在影子 API A 和 H 中，高级推理能力被显著削弱，与其声称"等同于官方 API"的说法存在明显偏离。

#### 敏感领域表现

在医学（MedQA）和法律（LegalBench）任务上，影子 API A、E、H 的平均准确率分别下降了 **16.96%**、**15.71%** 和 **14.75%**。其中，**Gemini-2.5-flash** 在所有影子 API 上都出现了明显退化。特别是在 MedQA 上，它的准确率从官方 API 的 **83.82%** 急剧下降到影子 API 的平均 **36.95%**，性能损失高达 **46.51%–47.21%**。在 LegalBench 上也出现了一致性崩塌：所有影子 API 都比官方端点低 **40.10%–42.73%**。

**DeepSeek-Chat** 同样表现出不稳定，尤其是在法律任务上。虽然影子 API E 与 H 相对稳定，但影子 API A 在 LegalBench 上仍出现了 **9.98%** 的准确率下滑。

论文第 5 页表 1 还列举了高风险领域中的典型失败案例：

* 在医学场景中，影子 API 混淆了 HIV 产时筛查中的确认性检测流程；
* 在法律场景中，影子 API 错误理解了陪审员诚实性相关判例。

这些结果表明，在专业高风险领域中依赖影子 API 提供建议，存在严重安全隐患。

### 4.3 安全性评估

#### 数据集与方法

作者采用两个常用安全基准：**JailbreakBench** 和 **AdvBench**，分别包含 **520** 条和 **100** 条有害请求，覆盖欺骗、歧视、身体伤害等不同风险类别，用于评估大语言模型在面对不安全用户请求时的安全能力。作者使用四种不同的越狱攻击来评估安全性：

* **GCG**
* **Base64**
* **Combination**
* **FlipAttack**

参考 PAIR、TAP、JAIL-CON 等工作，作者引入一个轻量级裁判模型来输出**危害性分数（harmfulness score）**，并判断生成的回答是否既有效又有害。该评估器基于 **GPT-4o-mini** 和 StrongREJECT 的基于规则的提示模板构建。危害性分数越高，表示回答越危险，模型安全性越低。

#### 结果

在 JailbreakBench 和 AdvBench 上，作者都观察到一种令人担忧的不一致现象：影子 API 与官方基线之间的偏离是**不可预测**的。

* 对 **GPT-5-mini**，在 **Base64** 攻击下，影子 API A 的危害性分数可达官方 API 的数倍；而在其他攻击下，又会出现对风险的低估。
* 对 **Gemini-2.5-flash**，所有影子 API 在所有攻击下都表现得比官方 API "更安全"，也就是对风险有**系统性低估**。例如，在 **FlipAttack** 下，官方 API 的危害性分数高达 **0.90**，而所有影子 API 只有 **0.67–0.68** 左右。
* 对 **DeepSeek-Chat**，影子 API 与官方 API 的差异较前两者略小，但仍明显存在：在某些攻击下会生成更多有害内容，在另一些攻击下又会生成更少有害内容。

### RQ2 结论

性能评估表明，**影子 API 不能替代官方 API**。它们不仅经常在推理任务上失效，而且在医疗、法律以及安全评测中都表现出不可靠性。

## 5 模型验证

为回答 RQ3，作者不再只依赖间接的性能信号，而是通过**模型指纹识别**和**元信息比较**来直接验证这些服务背后实际提供的模型身份。

### 5.1 基于指纹的检测

为了识别影子 API 服务商实际调用的是哪一个 LLM，作者采用 **LLMmap** 这一主动式指纹识别框架。该框架通过向模型发出一组精心挑选的查询，分析回答并计算输出与参考数据库之间的**余弦距离**，从而对模型进行分类。作者基本遵循 LLMmap 的原始配置，并扩展了其中的模型列表。对于 GPT-5-mini、GPT-5、Gemini-2.5-flash 和 Gemini-2.5-pro，作者去除了不受支持的参数，并统一设置为默认的 **medium reasoning effort**。

作者在 **24 个** 被评估端点上发现，影子 API 的模型身份可靠性差异显著。总体来看：

* **45.83%** 的端点**未通过指纹验证**
* 另有 **12.50%** 的端点虽然未直接错配，但与官方模型相比表现出显著偏大的余弦距离。

从模型家族角度看，**GPT** 和 **DeepSeek** 家族中身份错配更频繁。即使影子 API 被识别在同一模型家族中，它的余弦距离也常常膨胀。例如，影子 API A 中的 **GPT-5-mini** 的距离为 **18.63±2.72**，而官方基线为 **14.57±3.82**。相比之下，**Gemini-2.5-pro** 在各个服务商之间相对稳定。

作者进一步指出，影子服务商常见的欺骗方式主要有两类：

第一类，是把高价的专有模型偷偷替换成更便宜的开源或低成本替代品。例如：

* 影子 API H 中声称的 **GPT-4o-mini**，其行为特征更接近 **Qwen2.5-7B**
* 影子 API A 和 E 中的 **GPT-5**，其指纹更像 **GLM-4** 或 **DeepSeek-V3**。

第二类，是把带推理能力的专门模型，替换成不具备相同推理能力的普通模型。例如：

* 通过影子 API A 和 H 请求 **DeepSeek-Reasoner** 时，返回行为却更像 **DeepSeek-Chat**
* **Gemini-2.0-flash** 也经常被误识别为 **Gemini-2.5-flash**。

这些证据共同表明，影子 API 的模型身份存在用户难以可靠验证的不一致性。

### 5.2 补充性验证

为了弥补单一指纹方法可能存在的盲点，作者进一步采用 **Model Equality Testing（MET）**。MET 会对影子 API 输出与官方模型输出是否来自同一分布进行**双样本假设检验**。如果拒绝"分布相等"的原假设，就说明影子 API 的输出在统计意义上可与官方模型区分，从而构成另一种独立的身份不一致证据。

作者在三个影子 API（A、E、H）上，对四个基准（AIME 2025、GPQA、AdvBench、JBB）进行了评估。结果表明，**MET 与 LLMmap 在 74.1% 的案例中达成一致（40/54）**，Cohen's κ 为 **0.512**，说明两种独立方法之间具有中等到较强的一致性。

MET 的结果总体上支持了指纹识别的发现。例如：

* 影子 API A 中的 **GPT-4o-mini** 和 **GPT-5**，在 AIME 2025 与 GPQA 上都被判定与官方输出在统计上显著不同；
* **DeepSeek-Chat** 几乎在所有提供商—基准组合中都被拒绝通过；
* **Gemini-2.5-pro** 在三个提供商的 AIME 2025 和 GPQA 上都未被拒绝，说明在被评估的影子 API 中，这一模型相对更忠实地被提供出来；
* 但 **Gemini-2.5-flash** 在安全基准上却呈现相反模式：MET 在所有服务商上都拒绝原假设，说明即便表面能力输出看起来相似，其安全行为仍发生了显著偏离。

### 5.3 元信息分析

作者还分析了**推理延迟时间**和**token 数量**。官方 API 对同一问题通常具有相对稳定的推理时延和 token 数，而影子 API 则会出现不规则的尖峰。标准差分析进一步证明了这种不稳定性：影子 API 的波动经常超过官方 API 的 **2 倍**。

### RQ3 结论

模型验证提供了影子 API 欺骗行为的**直接证据**：将近一半的影子 API 无法通过指纹验证，而且它们的推理延迟和 token 数也明显偏离官方模型。作者还在一个已知真值的受控测试环境中验证了两种检测方法：**LLMmap 的准确率为 96.0%**，**MET 的准确率为 88.3%**，且两者在所有已确认的替换案例上都给出了相同判断。

## 6 讨论

### 6.1 联合分析

作者综合性能评估与模型验证结果，分析"模型身份"与"性能偏差"之间的关系。某些情况下，身份匹配确实会伴随行为一致。例如，在影子 API E 中，**GPT-5-mini** 的指纹与声称模型一致，而且其在敏感领域中的表现也与官方端点差异不大。

反过来，当模型身份不匹配时，性能往往也会相应恶化。例如：

* 影子 API A 中的 **DeepSeek-Reasoner** 被识别为 **DeepSeek-Chat**
* 同时它在 **AIME 2025** 上的准确率显著下降
* 类似现象也出现在影子 API H 中的 **GPT-4o-mini**。

不过，作者也强调，这种对应关系并不总是稳定存在：

* 模型替换**不一定**立刻表现为性能大幅下降；
* 相反，**身份匹配也不保证行为忠实**。最典型的就是 **Gemini-2.5-flash**：在 A、E、H 三个影子 API 中，它的指纹与官方模型家族相符、余弦距离也接近官方 API，但在敏感领域中的准确率却大幅下降。

作者还对所有 24 个端点做了 OLS 回归，试图用余弦距离、价格比、身份错配与是否为推理模型来预测准确率下降。结果表明，**价格没有预测能力**，而 Gemini-2.5-flash 是一个关键的结构性异常：它把"指纹忠实度"和"行为忠实度"分离开来。

### 6.2 经济激励与用户损失

作者认为，影子 API 服务商主要通过三种机制利用用户对模型身份的信息不对称：


1. **信息溢价（Information Premium）** 服务商对外声称提供某模型，却暗中用另一种更便宜但看似更新或能力相近的模型替换，并收取更高价格。
2. **折价替换（Discount-Substitution）** 服务商按官方价格收费，却用廉价开源后端替换高价模型。
3. **转售加价（Resale Markup）** 服务商在加价转售的同时，仍然进行静默替换。

为了量化模型替换带来的经济损失，作者分析了 **GPT-5 在 GPQA 上的 1,273 次查询**，并按官方价格估算实际交付价值。结果显示：

* 官方 API 的等价价值是 **$14.84**
* 影子 API A 只有 **$5.70**
* 影子 API E 只有 **$5.35**
* 影子 API H 只有 **$7.77**

也就是说，用户即便按官方价格付费，也可能只收到 **36%–52%** 的真实输出价值；按任务准确率归一化后，影子 API 每单位实际价值带来的错误数甚至是官方端点的 **2–4 倍**。

作者的数据集中共有 **187 篇** 论文依赖通过影子 API 获得的 LLM 流程。即便保守假设其中只有 **30%** 的论文在检测到身份不一致后需要重新执行（约 **56 篇**），其直接成本——包括 API 重跑费用与研究者时间成本——就可达到 **11.5 万到 14 万美元**。

## 7 建议

作者指出，影子 API 的欺骗行为已经相当普遍，而且在技术上可被检测、在经济上有明确动机。为保护基于 LLM 的研究完整性，他们提出面向审计者和研究者的两套流程。最核心的建议非常明确：**研究流程中不应使用影子 API，根本解决方案是直接使用官方 API。**

### 审计者验证协议

作者建议采用四阶段验证流程；只要某一阶段被标记异常，就应升级为避免使用该端点。

第一阶段：使用至少 **24 个 LLMmap 探针**查询端点。若余弦距离超过官方基线的 **1.2 倍**，或 top-1 识别模型与声明身份不一致，则判定可疑。

第二阶段：使用 **MET**，样本数至少 **500**，显著性水平 **α = 0.05**。若拒绝"分布相等"的原假设，则应标记该端点。

第三阶段：在留出基准上至少进行 **3 个独立会话**。如果准确率标准差超过 **5 个百分点**，或延迟变异系数超过 **0.15**，则说明后端路由不稳定或存在动态模型替换。

第四阶段：验证 **ICP 注册**与**法律实体披露**。若端点由未注册个人运营，且无法核实来源，则其法律与运营风险更高。

### 研究者预注册清单

对于任何依赖 LLM API 查询的研究，作者建议在正式收集数据前公开报告以下信息：

* 完整端点 URL
* 声称的模型版本
* 访问日期
* 定价档位

并且，在任何实验查询开始之前，该端点都应先通过上述四阶段协议。若某端点未通过任一阶段，则其结果不应被报告为"代表所声称模型"。此外，研究结果旁还应附带：

* 至少三次独立运行的准确率
* LLMmap 指纹余弦距离
* MET 的 p 值

### 社区层面的行动

作者呼吁研究社区采取更结构化的保障措施。会议组织者和程序主席应修改审稿指南，将**未披露或未经验证的第三方 API 端点**视为一种复现性风险，类似于未核实的数据集来源。同时，官方模型提供商也可以通过放宽地域访问限制、提供学术定价、以及提供轻量级官方验证端点来减少影子市场需求。


---

## 8 结论

本文首次对影子 API——这一被广泛使用但未被验证的前沿 LLM 非官方接入方式——进行了系统审计。通过跨服务商、跨基准、跨多维度行为指纹的综合评估，作者证明影子 API 在性能和身份上都存在显著不一致。依赖影子 API 进行评估是不可靠的，因为它们可能无法复现官方端点的行为。综合来看，这些结果揭示了影子 API 存在欺骗性的模型声明，因此不能把它们当作可靠的官方模型替代品。

## 局限性

尽管本文对影子 API 做了系统审计，但仍存在若干限制。

### 时间范围与市场波动

本文只反映了 **2025 年 9 月到 12 月** 这一特定时间窗口内的影子 API 快照。影子 API 市场具有极强的不透明性：服务商会频繁更换上游模型、改变路由策略，甚至无预警停止运营。因此，随着市场变化，这些服务的行为特征可能在观察窗口之外发生显著漂移。作者之所以采用固定时间窗口，是为了保证各基准与各服务商之间的实验一致性。尽管具体分数可能随时间变化，但作者认为，他们记录到的核心风险信号——不透明的模型替换、能力降级和安全行为分歧——反映的是服务设计与运营中的**结构性不透明**，而非某个测量时点的偶然现象。

### 检测覆盖与真值缺失

由于无法获得影子 API 后端基础设施的真实情况，作者只能依靠性能指标、元信息以及 LLMmap 和 MET 这样的审计框架来检测模型替换和性能不一致。因此，虽然他们可以高置信度地发现身份错配，但无法最终确认某些更细粒度的实现细节。另外，即便作者尽量精确记录了官方模型版本，专有模型的官方 API 仍可能存在未公开的微调更新。为减轻时间漂移与随机性的影响，作者对每个实验都进行了多次独立运行并报告方差。

### 服务商与模型家族覆盖范围

作者是根据学术引用量和 GitHub stars 收集到 17 个服务商的，但这可能仍无法覆盖全部影子 API 市场。市场中还可能存在采用其他技术架构或欺骗策略的服务。与此同时，本文也未能覆盖所有 LLM 家族，而主要聚焦于三个有代表性的模型家族。作者认为，他们的审计流程和发现有潜力推广到更多模型家族。

## 伦理考虑

作者表示，本文遵循负责任的 AI 研究准则。研究过程中，他们确实购买并查询了非官方影子 API 服务，而这可能违反官方提供商（如 OpenAI、Google、DeepSeek）的服务条款；但这些交互仅用于审计与透明化目的，并不构成对这些服务的支持、推广或鼓励。为尽量减少对官方基础设施的负面影响，作者将查询量严格限制在统计验证身份和性能所需的最低范围内。此外，所有对官方 API 的请求都只从获授权的地区发起，以确保符合提供商的地域访问政策。

为避免变相为非法服务做广告、并降低个体运营者面临的法律风险，作者对所有被审计的影子 API 进行了严格匿名化。他们的目标是揭示影子 API 市场中的系统性风险，而不是针对特定个人。对使用影子 API 的论文、作者和机构，作者同样做了去标识化处理，目的是强调学术共同体中的系统性复现性问题。

在安全评估中，作者使用了越狱攻击测试模型防护能力。为防止滥用，他们没有公开成功生成的有害内容示例，也没有披露可绕过安全过滤器的具体对抗提示，只报告了聚合指标和危害性分数，并将敏感输出保存在受控本地服务器中。

最后，作者表示他们遵循了负责任披露原则，致力于把发现反馈给官方模型提供商以及使用影子 API 的论文作者，并已收到部分确认回应。

进一步的标准差分析表明：


1. **延迟时间波动更大**：影子 API 的推理延迟明显不稳定，其波动程度经常超过官方基线的 **1.2 倍**，有时甚至超过 **2 倍**。
2. **Token 数波动异常**：在某些基准上，GPT 系列模型的 token 方差异常偏低；而在另外一些基准上，Gemini 和 DeepSeek 模型则表现出过大的 token 方差。

这一附录的重要意义在于：即使某些影子 API 在文本表面上看起来与官方 API 相似，它们在**延迟模式**和**生成长度**上仍可能露出明显的不一致。

## 附录 F：检测方法的受控验证

附录 F 在**已知真值**的条件下测试两种检测方法是否可靠：

* **LLMmap**
* **MET（Model Equality Testing）**

作者搭建了一个本地受控测试平台，覆盖 **GPT、Gemini、DeepSeek** 三个模型家族，并设计了三类"诚实 / 欺骗"场景。每个场景都包含 **100 个样本**。

### 受控场景

#### 诚实场景

* 声称 GPT-5，后端也确实是 GPT-5
* 声称 Gemini-2.0-flash，后端也确实是 Gemini-2.0-flash
* 声称 DeepSeek-Reasoner，后端也确实是 DeepSeek-Reasoner

#### 欺骗场景

* 声称 GPT-5，实际后端却是 GLM-4-9B（模型替换）
* 声称 Gemini-2.0-flash，实际后端却是 Gemini-2.5-flash（版本错配）
* 声称 DeepSeek-Reasoner，实际后端却是 DeepSeek-Chat（能力降级）

### 结果

**LLMmap** 在受控测试中的总体准确率为 **96.0%**。 **MET** 的总体准确率为 **88.33%**，略低于 LLMmap。

作者解释，MET 的漏报率较高，是因为它的设计目的并不是精确识别"到底是哪一个模型"，而是判断"输出分布是否与所声称官方模型一致"。因此，MET 更适合作为**补充检测**，而不是单独替代 LLMmap。

这一附录的意义是：正文对影子 API "欺骗性"的判断，并不只是建立在性能差异的猜测之上，而是建立在**经过受控验证、误报率和漏报率可量化的检测工具**之上。

## 附录 G：准确率下降预测因素的回归分析

附录 G 试图回答一个更细的问题：**到底哪些因素和准确率下降有关？** 为此，作者对全部 **24 个影子 API 端点** 建立了一个 OLS 回归模型，用来预测准确率下降。

### 自变量

* **余弦距离（Cosine Distance）**
* **价格倍率（Price Ratio）**
* **身份错配（Identity Mismatch）**
* **推理模型标记（Reasoning Model）**

### 结果

在全量模型中，**没有任何单一变量达到传统显著性阈值**，整体解释力也不高（R² 较低）。

作者认为，这主要是因为一个关键的**结构性异常**：**Gemini-2.5-flash** 在三个影子 API 上都出现了近 **47% 的严重准确率崩塌**，但与此同时，它又**持续通过了 LLMmap 指纹验证**。

这说明一个非常重要的结论：

**"身份一致"不等于"行为忠实"。**

当作者把这几个 Gemini-2.5-flash 异常点从回归中剔除后，模型拟合明显改善，且**身份错配**开始变得边际显著。这更符合作者的总体假设：在排除特殊异常后，**模型身份替换确实是准确率下降的重要驱动因素之一**。

作者还指出，**价格倍率对准确率下降没有预测力**。这意味着用户不能靠"选更贵的影子 API"来降低踩坑风险。

此外，作者还分析了 **MET 拒绝率** 与 **准确率下降** 之间的关系，发现二者只有很弱的相关性。这说明 MET 与准确率下降反映的是**互补维度**，而不是冗余信号。

## 全文总结

综合全文，作者的核心结论可以概括为：


1. **影子 API 已被大规模真实使用**：17 个影子 API 出现在 187 篇论文中。
2. **它们并不可靠地复现官方 API**：在数学、科学、医学、法律和安全评测中都存在明显偏差。
3. **不只是"表现不一样"，而且"身份可能不对"**：大量端点未通过指纹验证，或输出分布与官方显著不同。
4. **价格不是质量保障**：更贵的影子 API 并不更忠实。
5. **学术复现性会因此受损**：基于影子 API 的研究结果，可能并不真正代表所声称的官方模型。

作者最终的立场非常明确：**影子 API 不能被视为官方模型 API 的可靠替代品。**
